# Agent 工作流耗时诊断报告

## 适用场景

面向负责排查 Agent 请求延迟的开发者。先用端到端 P95 与超时率了解这批请求的整体表现，再用慢请求的阶段占比定位累计耗时最高的步骤，最后在最慢的几次运行中核对分阶段记录。

示例假设规划、检索、工具执行和结果生成依次串行执行。存在并行节点的工作流应使用跟踪系统记录的实际起止时间计算端到端耗时，并采用能够反映重叠时间的归因口径。

## 输入与数据口径

案例内置 20 次模拟运行。每条记录包含唯一运行 ID，以及四个阶段的毫秒耗时。所有指标、条形图和明细都从这批记录计算。

| 指标 | 统计范围和算法 | 样例结果 |
|---|---|---|
| 端到端耗时 | 每次运行的四阶段耗时之和，单位为 ms | 最慢一次为 3,600 ms |
| 端到端 P95 | 全部 20 条按端到端耗时升序排列，最近秩为 `ceil(0.95 × N)`，取第 19 条 | 3,200 ms |
| 模拟超时率 | 端到端耗时达到 3,000 ms 的运行数除以总运行数。模拟记录保留全段观测 | 2 / 20 = 10% |
| 慢请求 | 端到端耗时达到 2,000 ms 的运行 | 4 条，共 11,740 ms |
| 慢请求的阶段占比 | 该阶段在 4 条慢请求中的累计耗时除以 11,740 ms。按原始占比排序，展示时再取一位小数 | 工具执行为 7,170 / 11,740，显示为 61.1% |
| 最慢运行明细 | 按端到端耗时降序取前四条。同耗时按运行 ID 排序 | run-20、run-19、run-18、run-17 |

## 实现步骤

1. 为每条运行汇总端到端毫秒数，再按阈值分别计算全量超时率和慢请求样本。
2. 将 P95 与超时率放在指标卡中。按阶段汇总慢请求的耗时，按占比降序绘制横向条形图。图的比例尺从 0% 到 100%，重点色标出占比最高的阶段，结论文字给出同一阶段及占比。
3. 在明细表中逐条给出慢请求的端到端耗时、分阶段耗时和模拟超时状态。窄屏下横向滚动表格，保留完整字段。
4. 让页面加载 [TypeScript 示例](../examples/scenarios/agent-workflow-latency-diagnosis.ts)，并提供空的 `<div id="container"></div>`。示例使用原生 DOM 创建容器和表格，再使用 G2 v5 渲染条形图。参考 [条形图组件](../charts/bar.md)与 [G2 v5 API 速查](../references/g2-v5-cheatsheet.md)。

## 易错点

- P95 基于各次运行的端到端耗时。将各阶段各自的 P95 相加会改变指标含义。
- 阶段占比是慢请求子集中的「总和除以总和」。逐条算占比再取平均会给快慢不同的请求相同权重。
- 两个阈值都包含边界。耗时达到 2,000 ms 的请求进入慢请求分组，达到 3,000 ms 的请求计入模拟超时。
- 图表和文字使用同一份计算结果。占比展示四舍五入后，各项之和可能与 100% 相差 0.1 个百分点。
