# 模型升级回归评审报告

## 适用场景

模型版本发布维护者在同一批样本上验证旧版和新版，判断新版是否满足示例发布门槛，并定位需要复核的质量回归和延迟异常。

指标卡汇总通过率、修复与新增失败。门槛表列出通过率、关键回归、单任务降幅和 P95 延迟的判断。两张条形图解释任务差异，环形图和明细表追踪新增失败，箱线图与延迟表定位耗时变化，热力图按样本 ID 核对两版判定。

## 输入与数据口径

案例内置独立编写的 24 条测试数据，分为简答生成、字段提取和指令遵循三类。统计范围为同一评审批次，两个版本各对每条用例判定一次，使用同一通过标准。样本数据仅用于演示页面与计算。

| 字段 | 含义 |
|---|---|
| `id` | 用例唯一 ID，用于匹配两个版本的判定 |
| `task` | 任务类别 |
| `name` | 用例名称，用于人工复核 |
| `critical` | 评审前确定的关键用例标记 |
| `baseline` / `candidate` | 旧版 / 新版判定，`true` 表示通过，`false` 表示失败 |
| `baselineMs` / `candidateMs` | 模拟的两版端到端耗时，从发起请求到完整响应，单位为毫秒。通过和失败样本都计入。 |
| 判定证据 | 按新增失败的样本 ID 提供模拟输入、预期和两版输出，用于复核原判定 |

| 指标 | 统计口径 |
|---|---|
| 整体通过率 | 该版本通过的样本数 ÷ 全批次样本数 × 100，单位为 % |
| 各任务通过率 | 该版本在对应类别通过的样本数 ÷ 该类别的样本数 × 100，单位为 % |
| 整体通过率变化 | 新版通过率减去旧版通过率，单位为百分点 |
| 修复数 | 旧版失败、新版通过的样本数，单位为条 |
| 新增失败数 | 旧版通过、新版失败的样本数，单位为条 |
| 关键回归数 | 新增失败且 `critical` 为真的样本数，单位为条 |
| 持续通过 / 持续失败 | 两个版本都通过 / 都失败的样本数，单位为条 |
| 新版失败构成 | 新增失败数与持续失败数分别除以新版失败总数，单位为 % |
| 单任务最大降幅 | 对每类任务计算旧版通过率减新版通过率，取其中最大值，最小为 0，单位为百分点 |
| P50 / P95 延迟 | 对每版全部耗时升序排序，用零基位置 `(n - 1) × p` 取分位数，非整数位置在相邻值间线性插值。单位为毫秒。 |
| 耗时增幅前三 | 按同一用例的新版耗时减旧版耗时降序排列，取最大的三条正值，单位为毫秒 |

本案例的放行门槛为整体通过率 ≥ 80%、关键回归 0 条、单任务最大降幅 ≤ 10 个百分点、P95 延迟 ≤ 800 ms。任一项未通过即暂缓发布。示例耗时和阈值用于演示评审口径。

## 实现步骤

1. 按 `id` 对齐结果，每条样本保留唯一一对判定，并归入持续通过、修复、新增失败或持续失败。从同一批配对结果派生所有指标、图表和明细。百分比在展示时最多保留一位小数。
2. 从空的 `#container` 用原生 DOM 和 CSS 创建评审区、指标卡、图表容器和明细表。先把容器加入页面，再创建 G2 v5 图表。每个图表父容器由 CSS 设置高度，并使用 `Chart({ container, autoFit: true })`。
3. 根据下表组织 [长表数据](../references/data-patterns.md)。通过 AntV 上下文检索服务核实 `dodgeX`、`stackY`、`theta`、`cell`、`boxplot` 和 `autoFit`，组合用法参见 [G2 v5 API 速查](../references/g2-v5-cheatsheet.md)。
4. 逐项计算门槛结果，把未通过的指标链接到对应图表或明细行。原生表格标出新增失败的级别，通过「判定证据」展开用例输入、预期和两版输出。

| 图表 | 回答的问题 | 图表规则与分支案例 |
|---|---|---|
| 任务通过率 | 哪个任务退化了？ | [条形图规则](../charts/bar.md) · [分组条形图](../examples/bar/grouped.ts)。按任务和版本计算通过率，用 `interval`、`dodgeX` 和 `transpose` 并排呈现，轴范围固定为 0%～100%。 |
| 任务结果变化 | 一个任务有多少修复和新增失败？ | [条形图规则](../charts/bar.md) · [堆叠柱状图示例](../examples/column/stacked.ts)。组合 `stackY` 与 `transpose` 横向堆叠，各段合计等于该任务样本数。 |
| 新版失败 | 新版失败里有多少是本次新增的？ | [饼图规则](../charts/pie.md) · [环形图](../examples/pie/donut.ts)。用 `stackY`、`theta` 和 `innerRadius` 呈现新增与持续失败，中心展示新版失败总数，明细表列出新增失败。 |
| 端到端延迟 | 典型耗时和尾部是否往同一方向变化？ | [箱线图规则](../charts/box.md) · [基础箱线图](../examples/box/basic.ts)。每版 24 个原始观测交给 `boxplot`，按版本对照分布，分位表与增幅表提供精确数值和对应样本。 |
| 样本结果 | 怎样逐条复核两版判定？ | [热力图规则](../charts/heatmap.md) · [带标签的热力图](../examples/heatmap/with-label.ts)。用 `cell` 按完整样本 ID 和版本绘制，把新增失败的用例排在前面，用颜色和符号表示判定。窄屏下可在矩阵区域横向滚动。 |

参考 [shadcn 的组合原则](https://github.com/shadcn-ui/ui/blob/main/skills/shadcn/SKILL.md#principles)，复用上述 G2 图表与原生表格。两张条形图共用任务顺序，存在关键回归的任务排在前面，其次是有其他新增失败的任务。结果配色由同一份配置提供，新增失败的颜色也用于关键回归标记。该示例是一次性挂载的静态报告。

## 易错点

- 汇总通过率按全批次样本数计算。直接平均各任务通过率会给样本数较少的任务同等权重。
- 同一任务的通过率可能持平，同时出现修复和新增失败。新增失败需要检查逐条判定，两个版本都失败的用例不计入。
- 环形图只统计新版失败的样本，分母是新版失败总数。
- 接入实际评测结果时，先检查 ID 唯一性和版本配对完整性。缺少判定的用例不可直接当作失败计入本口径。
- 图表数值保持为数值类型，在刻度和标签处添加百分号。通过率变化用百分点表示。
- P95 由原始耗时计算。箱线图按四分位距确定须和异常点，发布门槛使用分位表中的精确数值。

### 运行方式

使用 Node.js 22.12 或更高版本，在仓库根目录运行。临时预览页只提供空容器和模块入口。

```bash
npm install
mkdir -p temp
cat > temp/model-regression-review.html <<'HTML'
<!doctype html>
<html lang="zh-CN">
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>模型升级回归评审报告</title>
<div id="container"></div>
<script type="module" src="/examples/scenarios/model-regression-review.ts"></script>
</html>
HTML
npx --yes vite@7 --host 127.0.0.1 --port 5173 --strictPort
```

在浏览器打开 `http://127.0.0.1:5173/temp/model-regression-review.html`。

### 核对结果

| 项目 | 旧版 | 新版 |
|---|---:|---:|
| 整体通过 | 18/24（75%） | 20/24（83.3%） |
| 简答生成 | 6/10（60%） | 9/10（90%） |
| 字段提取 | 6/8（75%） | 6/8（75%） |
| 指令遵循 | 6/6（100%） | 5/6（83.3%） |

整体通过率提高 8.3 个百分点。修复 4 条（`QA-07`、`QA-08`、`QA-09`、`EXT-07`），新增失败 2 条（`INS-06`、`EXT-06`）。字段提取通过率保持 75%，其中一条修复抵消了一条新增失败。关键用例 `INS-06` 由通过变为失败，触发暂缓发布。

| 任务类别 | 持续通过 | 修复 | 新增失败 | 持续失败 |
|---|---:|---:|---:|---:|
| 简答生成 | 6 | 3 | 0 | 1 |
| 字段提取 | 5 | 1 | 1 | 1 |
| 指令遵循 | 5 | 0 | 1 | 0 |

新版失败共 4 条，其中新增与持续失败各 2 条，环形图各占 50%。热力图有 48 个判定格，`INS-06` 与 `EXT-06` 的新版判定格标为新增失败。使用鼠标点击或键盘激活「复核 INS-06」，页面定位到对应明细行，该行会获得焦点并高亮。

| 耗时指标 | 旧版 | 新版 |
|---|---:|---:|
| P50 | 525 ms | 494 ms |
| P95 | 658.5 ms | 863 ms |

耗时增幅前三是 `INS-05`（+360 ms）、`INS-06`（+230 ms）和 `EXT-08`（+45 ms）。`INS-05` 两版都通过，仍是耗时增幅最大的一条。四道门槛中仅整体通过率通过。关键回归 1 条、指令遵循下降 16.7 个百分点、新版 P95 为 863 ms，均超出示例门槛。选择「P95 延迟」可定位到延迟区，展开 `INS-06` 的「判定证据」可查看新版补出了输入中缺失的日期。
